# dsh-task-tree

**中文** | [English](README.en.md)

会话任务树：把一件活摆成能看懂、也能打断纠正的方向图——一眼看清现在做到哪、这活替谁做、旁边还有哪几件。

它不替模型想，它只把方向摆出来：下一级替上一级完成目标里的某一条，上一级是下一级的目的，验收留在父身上；左右是平级——同一个父下的 ①②③ 合起来把上一级做成。

## 它解决什么

模型做着做着就偏，通常不是能力问题，是方向丢了：本来在验收根目标，跑去做一个顺手看见的小问题；或者一件事拆出两组，混着做，两边都半截。任务树把每一步的「替谁做、做到哪、旁边还有谁」摊在侧栏和系统提示里，偏了能当场看见、当场挂回去。

## 能力

| 形态 | 名称 | 说明 |
| --- | --- | --- |
| 工具 | `task-tree` | `read` 读树／`new` 立树／`add` 挂节点（写 `serves`）／`move` 改挂父／`set` 改标题与目标／`drop` 整支移除／`align` 同步对齐栏／`unplaced` 未归位登记／`check` 体检／`export` 写工作区 `任务树.md`／`list` 列各会话的树 |
| 命令 | `/task-tree [--all\|--check]` | 手工查看 |
| 技能 | `task-tree-workflow` | 用法与硬规则（正文在 `assets/`） |
| 注入 | 系统提示 section | 带本会话的树（最多 14 个节点）与对齐栏；对齐栏给可照抄的整块，行名加粗、内容不加粗；根还是占位时顶一行提醒 |
| 面板 | 侧栏「任务树」标签页 | 画本会话的树；点卡片改本层目标／基本点／软硬需求与状态，保存即写回 |

## 对齐栏

节点字段就是那一层的对齐栏：

- `goal` 本层目标（回帖里的根本目标行由父节点带出）
- `accept` 验收（跟本层目标同一行）
- `points` 基本点、`hard` 硬需求、`soft` 软需求
- `serves` 替父拿下父目标里的哪一条

出示对齐栏的同一轮用 `align` 同步；有树时写到当前层节点，没立树时只存会话级快照，侧栏照样显示。根已有子支时直接改根目标会被拒（防逐轮漂移）；目标写偏要纠回来，显式带 `id=<根id> force=true why=<偏在哪>`，原来那句留一行「目标修正前」。

挂子之前先走三问：是当前这层要完成的目标之一就挂这层；不是就往上一层问；一路都不是、只是这件事带出来的问题 → 不挂成子，源不是根就 `add from=<源id>` 挂成源节点的平级，源是根就 `new unrelated=true from=<根id>` 另立一棵。父没有目标时不许挂子。

## 节点状态

`active` 运行中／`pending` 排队中／`done` 已定／`obsolete` 已废／`dropped` 已否。

全树只有一个「运行中」（进行中链的末端），其余没做完的显示「排队中」；已废的卡灰暗显示、不参与「现在做到哪」。

## 数据位置

- `$DSH_HOME/task-trees/sessions/<会话id>.json`（一个会话一个文件，不跨会话、不进工作区）
- 只有显式 `action=export` 才写工作区 `<工作区>/任务树.md`

## 模式门

树的注入与工具都按会话实时模式收口：判据读 Session 投影里的 `agentPreset`。

- 只对 `evolve` 模式注册 `task-tree` 工具并注入树与对齐栏；别的模式里工具从未注册过、也没有注入，不建根。
- 判不出模式时按「不是本模式」处理（宁缺不漏），下一次 `pre-step` 再判。
- 工具是按 agent 作用域注册的，不是先全局注册再摘——别的模式第一步就看不到它。
- 要让别的模式也用树：改 `index.js` 里的 `ALIGN_PRESET`。
- 侧栏面板是浏览器 UI，不跟模式走，不影响别的模式。

## 安装

```sh
dsh plugin --profile desktop add dsh-task-tree
```

装完重启 DSH。要求 DSH >= 0.2.1-alpha.1。面板是浏览器半边，`lib/client.js` 已随包提交，不需要构建。
