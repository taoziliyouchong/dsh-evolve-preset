# task-tree-workflow

**任务树＝把一个任务摆成你能看懂、也能打断纠正的方向图**：下一级替上一级完成目标里的某一条（验收留在父身上），上一级是下一级的目的；左右是平级——同一个父下的 ①②③ 并列摊开，合起来把上一级做成。它只为一件事存在——让你一眼看清：**现在做到哪、这活替谁做、旁边还有哪几件**。

**树跟着会话走，一个会话可以并列挂几棵**：树存在 `$DSH_HOME/task-trees/sessions/<会话id>.json`，不跨会话共享、互不掺和；右侧栏「任务树」面板显示同一份（几棵时画在同一块画布上、左右并排，每棵上方一个「第 N 棵」小标，平移缩放共用一套）。**每会话开场会自动长出一根根节点**（占位名「本会话任务」，面板从第一轮起就有卡片）；真正立树时 `action=new title=<根任务>` 直接替换它，不报「已有树」；`align` 第一次同步时也会把目标填进这根根节点。两件互不隶属的活用 `new unrelated=true` 各立一棵，**谁也不顶掉谁**（不归档、不替换）。

## 结构：会话 → 树 → 节点（三层别混）

| 层 | 是什么 | 有没有目标 | 谁跟谁有上下 |
|---|---|---|---|
| 会话 | 容器，装这一次聊的 1..N 件事 | 没有 | 树与树**只有并列**，没有父子 |
| 树 | 一件事，一个顶层要拿到的效果（根节点） | 有，只有一句 | 树内部才是"下一级替上一级完成目标里的一条" |
| 节点 | 那一个层：字段即该层对齐栏 | 有 | 平级＝同一个父下并列 |

由此定的口径：

- **几棵树**：一件事 → 一棵树；两件事在根上罩不住同一句效果 → 两棵并列（别硬凑一个根）；由树里某件事带出来的问题（不归任何一层的目标管）→ `add from=<源节点 id>` 挂成源节点的平级（源是根时 `new unrelated=true from=<根 id>` 另立一棵），图上用横线标来路；两件事有联系（修它、答它、给它供料）→ 同一棵树里挂支写 serves。
- **对齐栏归属**：两行目标（根本目标＝上一级节点的目标／本层目标＝这一层的效果）、基本点、硬需求、软需求都相对**当前那棵树的当前层**算；会话界面里有多棵时，回复的树路径要写清是哪棵树、在第几层，否则层与层之间有歧义。
- **完成与移除**：做完了标 `done`（留灰、不删，旁边还看得见）；真不要了才 `drop` 那棵的根 id → 挪进 `task-trees/archived/`，可恢复。
- **当前树**：进行中的那棵就是当前；切换靠用户点侧栏标签，或我 `align` 时指定节点。

## 挂之前先走三问（2026-11-01）

从最近的一层开始往上问，三问定归属：

1. **它是当前这层要完成的目标之一吗？** 是 → 挂这层下面。
2. **不是，就往上问一层**：它是上一层要完成的目标之一吗？一层层问到根。哪一层认它是目标，就挂哪一层；两层都认，挂低的那层——谁直接用它，挂谁。
3. **一路都没有哪层认它是目标**，只是这件事带出来的问题 → **不挂成子**：
   - 源不是根 → `add title=<…> from=<源节点 id>`：挂在源节点的父下、与源节点**平级**，不写 serves，图上用一根横线连到源卡；
   - 源是根 → `new unrelated=true from=<根 id>` 另立一棵并列的树，同样用横线连到那棵根；
   - 还没想清是不是独立 → 先 `unplaced`。

判据是「父要完成的目标里有没有这一条」，不是「没有它父能不能完成」——要的是目标拆分，不是关键路径。

- 挂的时候必须写出：**替 [父] 拿下父目标里的哪一条**。写不出 = 前面某一问判错了，退回上一问，别硬挂。
- **衍生节点不写 serves**：它不认领父目标里的条目，靠 `from` 标来路；挂成子的才是步骤。
- **父没有目标不许挂子**：三问的第一问没有对象，工具会直接拒。先补父的目标（`align id=<父> goal=…` 或 `set id=<父> goal=…`）。
- **根的直接子节点只放根的直接交付物**；对交付物的加工、封装、复用，一律挂到那个交付物下面——下游不是同辈。
- **时间顺序不是树结构**：先做的不等于父，后做的不等于子；只看「谁用完谁」。
- 自检：把它平级挂在根下，顶层会不会混进两类性质不同的东西（产出物／对产出物的加工）？会 → 挂错了。

## 对齐栏与树是同一套

节点字段本身就是它那一层的对齐栏：

| 对齐栏 | 节点字段 |
|---|---|
| 本层目标（这一层要拿到的效果） | `goal`（上一级的那句即对齐栏里的「根本目标」，由树里的父节点提供，不另存） |
| 基本点 | `points`（「｜」分隔） |
| 硬需求 | `hard` |
| 软需求 | `soft` |
| 替父拿下哪条（父目标里的一条；衍生节点用 `from` 标来路） | `serves` |

- **面板顶部不再放对齐栏块**：顶部只留根任务标题、统计和刷新；对齐栏的显示与编辑都在卡片里，路径也不再显示在顶部（活动链仍高亮在树上）。**验收是唯一例外**：侧栏卡片不显示、也不编辑验收（`accept` 仍随会话记录保存，由工具与回帖对齐栏维护）。
- **goal 写法**：只写效果，不写「替谁完成什么目标」，也**不写「（第N层）」**——层级由树里的位置表达；回帖对齐栏也不写层号。
- **改在卡片里**：点开一张卡片，「编辑」可改本层目标（`goal`）／基本点／硬需求／软需求与状态（运行中／排队中／已定／已废），保存即写进本会话；编辑态里鼠标落在输入框／文本域上，滚轮滚的是那一块，不缩放画布；编辑态整张卡不跟画布平移——在卡片内按下拖动不会拖动画布，选字不受影响；**编辑态卡片沿用进入编辑前的大小**（宽由布局给、高取进编辑前量到的高度），表单在卡内滚动，点「编辑」时节点不缩小。
- **回帖对齐栏两行目标（2026-10-25 定，2026-11-01 行名加粗）**：「**本层目标**：这一层要拿到的效果。验收＝…」每轮都出，验收跟本层目标同一行；当前节点有上一级（父节点有目标）时，在它上面加一行「**根本目标**：」＝上一级节点的目标，从树里照抄、跨层不变。当前节点就是根时只有本层目标一行（没有上一级，不出根本目标）。行名与侧栏卡片字段的对应：卡片里的 `goal` 就是「本层目标」。
- **出示对齐栏的同一轮同步**：`action=align goal=<本层目标去掉层号后的效果句> points=<基本点｜分隔> hard=<硬需求> soft=<软需求>`。有树时自动写到当前层节点（也可用 `id` 指定）；没立树时只存会话级快照。
- **当前层怎么定（2026-10-20 修）**：进行中链的末端；没有一条完整链时取**最深的进行中节点**，不退回根。根是整棵树的目的，别拿它逐轮换活（那是把当轮子目标顶掉根，越走越偏）。日常推进别落在根上——先 align 到实际在做的那一支。**目标写偏了要纠回来**（换根＝同一条任务的纠偏，不是换任务，低频）：显式带 `align id=<根id> force=true why=<偏在哪>`，原来那句留一行「目标修正前」（注入里带 `[目标已修正]`）。改正后各支照旧，`serves` 只是提法跟不上的改措辞——不拆支、不默认 drop。
- **自动落盘（2026-10-19 起）**：每轮开局插件会从**上一轮回复**里抄回目标（优先「本层目标」）与三需求，写进会话快照与当前层节点——正常推进不必再手动 `align`；方向变了照常 `action=align` 覆盖（"用户版本优先"保护不变）。抽不到目标与三需求时保持原样，不写空值。写盘被拒（如根保护）不再静默：注入顶部报「上一轮对齐栏没落盘：原因」，树里那版就是旧的，别当已更新。
- **连续修改护栏（2026-11-09）**：连续改节点（`align`／`set`／`move`／`drop`）而没有 `new`／`add` 建立新目标时——第 3 次报提示并禁止写入、第 4 次放行仍提示、第 5 次禁止、第 6 次放行仍提示（单数拦、双数放）；`new`／`add` 成功即清零。被拦时先把这轮当新活：该挂支就 `add`、该立树就 `new`，不是绕开写入。
- **长思考 40 秒先交一版对齐栏（2026-11-09）**：一轮满 40 秒、模型还没吐正文时，插件会先往回复里插一版当前对齐栏（抬头「⏳ 思考超过 40 秒」）；这一版不是你写的，正文照旧给最终版，自动回写只认正文最后一版。

## 状态

- 底层四个：`active` 运行中｜`pending` 排队中｜`done` 已定｜`obsolete` 已废。已废的卡留在树上、灰暗、不参与「现在做到哪」，随时可改回运行中。
- **界面口径（2026-10-25 定）**：全树只显示一个「运行中」——当前在跑的那颗（进行中链的末端，与对齐栏同一口径）；其余没做完的（`active`／`pending`）一律显示「排队中」。卡片、顶部统计、注入文本、工具输出同一套，别处不另算一份。
- `dropped` 已否：`action=drop` 整支移出树，进底部「已否」行，不再并列展示。
- 状态在卡片里改，保存即写回；下一轮注入按新状态走。

## 卡片里改完之后（会话侧固定动作）

1. **先复述**：说清把用户改成了什么理解成，不跳过。
2. **再重推**：按这一版重新推对齐栏与树——本层目标变了，基本点／硬需求／软需求跟着重推，当前层节点同步更新；需要润色可派子代理，也可自己改写。
3. **写回覆盖**：用 `action=align ... force=true` 写回（用户版受保护，不带 force 会被拒），并说清改了哪几句。
4. 用户没让改的地方不动；不趁重推夹带改别的内容。

## 什么时候立

- 本会话的活会拆出多级方向、值得用户打断纠正 → `action=new title=<根任务> goal=<根这一层要拿到的效果>`（根节点开场已自动长好，`new` 直接替换占位根；根没有目标就先补，不然挂不了子）；
- **新任务先走三问**（见上）：哪一层认它是目标就挂哪一层；一路都不是、只是这件事带出来的问题 → `add from=<源节点 id>` 挂成源节点的平级（源是根时 `new unrelated=true from=<根 id>` 另立一棵并列的树），图上用横线标来路；
## 用法四步

1. **挂任务**：`action=add parent=<父 id> serves=<替父拿下父目标里的哪一条>`；左右平级＝同一个父下的几件事，不分先后、互不依赖。父必须先有目标，否则先补父的目标。衍生出来的问题用 `add from=<源节点 id>`（挂成源节点的平级，不写 serves）；源是根就 `new unrelated=true from=<根 id>`。
2. **定位**：用户这句话落在哪个节点就只答那个节点；落到具体节点，不从根重开。
3. **写回**：结论 → `action=set`；对齐栏变更 → `action=align`；改挂父 → `action=move`；不要了 → `action=drop`。
4. **回复标路径**：一行「树路径＋当前节点」；渲染里已有「现在做到哪」行，不重复报全树。

## 硬规则

- **每个非根节点都要能答「替父拿下父目标里的哪一条」**（`serves`）：写不出＝这条边不成立，先问再挂。衍生节点除外——它写 `from` 标来路，不写 serves。
- **父没有目标不许挂子**：三问的第一问没有对象，先补父的目标。
- **说不清这件事挂哪：直接问用户**，不硬走、不默默不落盘。
- **没想清的**：`action=unplaced title=<这件事>` 登记（不进树，注入会带出来；满 2 条先归位再开新活）。
- **已否沉底**：`drop` 掉的（含整支）进「已否」行，不再并列展示，可回溯。
- **顺手体检**：`action=check` 报断链（没写替父拿下父目标里的哪一条）、父有子支却没有目标、同父下目标／标题一字不差（挂重了或复制串了）、状态倒挂（父已定子在做）、未归位。
- **谁写谁署名**：工具写的 `source=agent`、卡片里改的 `source=user`；用户版本优先，回写必须经他确认。

## 入口

- 每轮系统提示**自动注入本会话的树与对齐栏**（树最多 14 个节点，含「替父」链）；看全用 `action=read`（含「现在做到哪」行与对齐栏）。
- 手工查看：`/task-tree`（本会话）、`/task-tree --all`（各会话的树）、`/task-tree --check`（体检）。
- 右侧栏「任务树」标签页：根任务＋统计＋方向图（卡片里可编辑本层目标与三需求、改状态；不显示验收）。
