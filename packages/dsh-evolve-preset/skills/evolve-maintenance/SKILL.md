# 模式维护细则

模式正文（persona 键的正文）只留每轮要用的动作；这份技能承载“用到才需要”的规程。**正文说了要做什么，这里说怎么做。**

## 一、归纳怎么落地

判据（与正文通用性检查一致）：一件事**由我做、且会重复**（同判据／同换算／同拼装／同检查／同讲法）＝插件候选；机器已在做的不做，只此一回的不做。识别看行为证据，不看目录。

**构建素材的第一来源**：不是最终规则，而是「我这次怎么想到让你满意的答案」的那段推理——回看被否的版本与被接受的版本，找出中间做对了什么（换了什么判据、砍了什么、按什么顺序想），把那套顺序提炼成步骤与判据写进技能。只抄结论，技能会退化成判决表；抄推理，技能才会在下一次新问题上继续走得通。

验收只用两个率：识别率（该固化的认出来多少）、落地率（认出来的做出来多少）。识别靠数据——收尾跑一次 `repeat-scan`（插件 `dsh-session-search`：手跑脚本／重复长命令／高频工具排行；命令骨架已按路径／数字／引号归一），命中记一行「动作＋价值＋落点＋工作量」；确实没有才写“无新候选”。扫描只给候选，**不为了交差硬造**；有明确重复证据（同一动作第二遍、同一错误第二次）也可直接记，别等扫描。

形态与落点：要执行 → 工具；要“知道”才做 → 技能；要一键触发 → 命令。能并进现有插件就并，不为小事开新插件。默认个人插件（独立包目录：工具＋命令＋技能三件套），挂进 profile 的 bundles 全局可用；不改内置件（升级即覆盖）。落地用 `plugin-make` 一次走完 scaffold→wire→verify（没有该工具时串三步），做完报“做了什么＋怎么回退＋是否要重启”。

授权分级：新增能力、可回退动作（合并重复、改接线、加校验、给报告加节）直接做、收尾一句话报告；删除／停用／卸载、改用户文件或对外可见说明、影响面大或不可逆的先问一句。报告只报本轮，不重复报旧账。

文件落点由“它服务哪个项目／工作区”决定，不由技术依赖决定：借用别项目的代码或数据用只读引用，不为了跑通就把文件塞进那个项目，也不顺手改它的文档；工具产出（报告、明细、缓存）放它自己项目的目录；落点拿不准先问一句。

## 二、画像怎么写

两栏：要求、边界。

**判别**：正文那三关，这里说怎么落地。翻一步：看这句话落不落得到具体动作——说得出一句「我该做什么／不做什么」才是约束；只是感受、背景、描述，翻不出。一句里压着几条就拆几条。三关：破了会怎样，要说得具体（找不到文件、返工重来），说不出的就是空话；只此一次（这件事以后不会再碰）的不用记。单一任务／项目里长出来的，哪怕措辞通用也归任务画像或该空间的 CLAUDE.md。一次性教训、通用教学法、工作规则，以及我自己的操作条令（工具／步骤／格式／流程／形态）一律不写入画像。口令式触发词（“回到之前的”“一步步来”“值得商量”这类）不记画像、不进基本点，一律进术语字典（通用层或任务层）。

筛子只朝一个方向：收「他是什么人、他要什么、他的约束」，不收「我遇到某种情况该怎么反应」——反应协议归模式正文、流程归技能、口令归字典。自检问法：这条能不能在某个任务里逼出一条必须守的做法？别问「这条能不能指导我的行为」——后者会把对话协议、报告格式、流程口令全放进来，这就是画像里混进“不是基本点备料”的入口。

归位：通用条目（跨任务的做法与原则）→ `$DSH_HOME/evolve/user-profile.md`；领域条目（知识基线／交付手法／领域候选）→ `$DSH_HOME/evolve/user-profile.d/<类别>.md`。两边不互相混入。任务不属于任何现有类别时，允许新建 `<新类别>.md`：有了首条有据的领域条目才建文件，不预建空档。判某条归哪类，看那份画像标题下第一行「任务：…」。

铁律：只建立在跨多轮／跨会话的实际言行上；单次简短交互不下定论。两档——已确认（多次复现，可直接引用、写进画像）、待观察（一两次，只记录不引用、先不写进画像）；**档位由我按复现次数自动下，不问你（“已确认”＝复现够了，不是“你点头了”）**：跨会话复现 ≥2 次即升已确认；与特定项目强绑定的观察只在该会话记录。

写法：每条的主语落成「你……」——写你要什么、你是什么人、你的边界；主写成「我该怎么做」的先换主语，换不了的就不收。触发条件按语义写、不按原话写——动作才是判据，原话只当例子；口令式触发词不进画像，写进术语字典（`dict` `action=write`，通用层或任务层），触发时先查字典再执行，没进字典的一律按意思匹配。效果条目用你的原话，不翻译成我的术语；证据只取你的实际言行，判据够了当场落盘、不等你表态；你没碰过的类型写“待建”，不编造。

排版：纯文本框、不渲染 markdown——不加粗、不引用块、左对齐不缩进、一条一行、条目间留空行。改完跑 `profile-lint` 体检。

授权：写进画像不用问，收尾①报一句；要删掉或大改已有条目，先问。

画像外存：判据不收、又跟哪个项目空间都对不上号的内容 → `$DSH_HOME/profile-cloud/<主题>.md`（同主题并一文件；首条才建目录，不预建空档）。每条带四样：内容、排除原因（判据哪条）、来源（日期）、复活条件（什么情况升回哪里——跨领域复现→画像；跨任务规则→模式；有了归属的项目空间→搬进该空间的 CLAUDE.md）。它不是画像：开场不读、不进基本点；画像复审时顺带过一遍，已升格的当场删源条。

在判断里用：每轮你提要求，先在画像里找它对应哪一条——找到了按那条办；找不到，才是新条目的候选。条目从「用了几十次都对不上」里长出来，不从收尾检查项里挤。

复审与清账：收尾①画像项顺带扫一遍——有无已确认条目与本会话实际行为相反；有，报一句、说明哪条跟哪句对不上，不动手改，去留你定。只此一次的观察升成已确认，才写成条目。

## 三、改模式与整理

规则数只减不增：同类纠正复现＝判据没挡住 → 改写那一条，不追加新条；长期没挡下任何东西的规则直接删掉，不另记账。

改模式文字：只改本包 `cordis.patch.yml` 里 `preset-evolve` 声明的 persona 正文，不增删任何 `- id:` 行、不动 YAML 结构；改完跑 `preset-verify`，报 broken 立即回退。规则文字与技能正文只写规则本身：不附案例、示例与日期，不绑具体项目。改模式正文前先给用户看改哪句、为什么，点头再动。

模式私有的能力要按会话收口：宿主层插件对所有模式生效，注入类在 systemPrompt 文本回调里判会话投影 `agentPreset`（会话档头只是创建时的快照，切过模式就错），不是本模式就返回空串；工具类在 `agent/created` 与 `agent/pre-step` 里对非本模式的 agent 调 `agent.ctx.tools.restrict({ deny: [工具名] })`，切回本模式再释放；全局 hook 读 `task-tree` 在 `agent/created` 写的 `<会话id>.preset` 标记。判不出模式时按「不是本模式」处理，宁缺不漏。客户端面板要跟着收，得在浏览器半边用同一判据隐藏，只写一句「不是这个模式」不算收。

个人插件整体搬进 preset：profile 的 `dsh.profile.bundles` 只留 base、web-app 与本层包；每个包原 patch 里的 insert 行（id/name/config 原样）追加到 preset 的 `config.plugins`；profile patch 里针对同一行的 insert 或 config 覆盖同步删掉。preset 的行同样是 loader entry，浏览器照样加载包的 `./client`；工具、技能、命令、提示段随作用域只对本模式可见，宿主服务（webServer 等）沿作用域链照常注入。改完跑 `preset-verify`；profile 的改动会被运行中的实例热重载，搬迁期间的会话会暂时失去个人工具，改完要重启。

闲置工具只记账、不删：场景没出现过的工具保留，只有你点名才处置；清单以本机实际注册为准，每次核对时把已卸载的划掉、新闲置的补上。

## 四、收尾（与正文一致）

正文的收尾检测是**五项**：① 画像 ② 归纳 ③ 同频 ④ 待确认 ⑤ 词条；另加**一件文件落地**。

- 文件落地——本会话的临时脚本与中间产物，要么固化进插件或工具目录，要么删掉；只删本会话产物，不动你原有文件；你看过的交付物一律保留。
- 待确认闭环是第 ④ 项，不是单独一步：完成即删整行、过时即清、能做当场做。
- 五项过完＋文件落地完成，才算收尾完成。待确认项不写进模式文件，只在当轮对话里列。

## 五、环境坑文档（用户自建）

用户可在 `$DSH_HOME/env-pitfalls.md` 记本机环境坑，供自己排查时翻；它不进包、不进每轮上下文，模式不自动读。

写法：一级标题；开头一段「索引：主题＝小节号」；每节写「现象 → 试过的错方向 → 对的做法」。只记环境事实（哪个路径删不动、哪个工具缺席、哪个版本有坑），不记项目内容、不记一次性参数；版本相关的写清版本号与日期。
